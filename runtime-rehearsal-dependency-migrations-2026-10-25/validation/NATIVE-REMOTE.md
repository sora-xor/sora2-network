# Native production migration rehearsal

The prepared scope uses the same SORA Nexus production checkpoint as the exact-Wasm rehearsals: block **28,179,122**, hash `0x32fd0d8dd97744f86dcf9d964d7fcd25fea43ab5e6d9d7054db9b7b75eba8cd0`, deployed spec **134**, transaction version **131**. The public endpoint is `wss://mof2.sora.org`; the adjacent provider RDAP evidence records the inspected address under OVH Australia PTY LTD. This diagnostic endpoint does not establish validator hosting or independent consensus verification.

`prepare-native-remote.cjs` completed read-only preflight against that exact block. It independently checked genesis, canonical block number/hash, finalized height, runtime version and deployed code hash, then read all **76** metadata-visible FRAME storage-version keys, **five** legacy custom guards and **three** migration markers. The **19** audited versions and all custom guards matched the reviewed migration assumptions. Raw current responses are in `native-remote-scope.json`; historical 4.8.11 values serve only as explicit expectations, never as current evidence.

The state scope retains **23 complete pallet prefixes**, including Staking, XorFee, Liveness, all audited migration pallets, complete EthBridge, MultiBlockMigrations, Babe and Timestamp. It also retains every FRAME version guard, relevant System context, native total issuance and raw runtime migration markers. System accounts, account/token balances, unrelated pallet state and child tries remain excluded. An unexpected guarded legacy migration aborts preflight so its data dependencies can be reviewed before expanding the scope.

The runner uses `--locked --no-default-features --features std,try-runtime`, selecting production chain features with native migration checks added. The chain-spec development dependency also enables `common/test`: fixed-point balance conversion uses stricter unwrap/checked behavior, and common include macros use test fallbacks. This native lane therefore includes test instrumentation; exact default-production Wasm fork execution establishes production runtime semantics. It explicitly sets `REQUIRE_REMOTE=1`, `REMOTE_BLOCK_HASH`, `REMOTE_STATE_VERSION=0` from the captured runtime, and `REMOTE_UPGRADE_CHECKS=pre-and-post`. The trie version override prevents upstream's latest-head runtime-version query from selecting a different trie format for pinned historical storage; the constructed externalities must match it. The upgrade mode runs configured migration pre/post hooks and retained-state decoding through `Executive::try_runtime_upgrade(PreAndPost)`. It intentionally makes no global `try_state` claim on partial state. The existing test also checks bridge replay/index/bounds, audited final storage versions and completion of multi-block migration steps.

Before either native test, the runner resolves `cargo tree` with the same package/features and includes normal, build and development dependency edges. It records the graph/hash and fails if any resolved package enables `private-net`, `stage`, `wip`, `runtime-benchmarks` or reduced reward periods. The runtime node must include `std,try-runtime`; an unrecognized graph format fails closed. Five offline parser regressions cover clean development dependencies, contamination of the runtime or a dependency, missing requested features and unsupported output. No Cargo tree or native compilation is run by these parser tests.

After the build owner releases the existing warm target lane, run from the repository root:

```sh
python3 runtime-rehearsal-dependency-migrations-2026-10-25/validation/run-native-remote.py \
  --target-dir target --execute \
  --source-fingerprint runtime-rehearsal-dependency-migrations-2026-10-25/validation/source-clippy-start.json
```

Omit `--execute` to inspect the prepared commands without compiling or contacting the chain. Actual execution requires the build owner's final source fingerprint and checks the full source inventory before and after both tests. Every Cargo command runs through `scripts/with_llvm_env.sh` so the reviewed macOS LLVM loader environment is set immediately before Cargo. The runner first executes four option-selection regressions and then the exact native rehearsal. It refuses an existing snapshot file, rejects optimized Python, checks for silent skips, verifies the reported block/hash, and records command, environment, source checks, logs and the newly captured scoped snapshot hash. A matching cached header alone cannot demonstrate that an older cache contains the required prefixes. The complete build/source provenance and exact candidate Wasm are recorded separately by the build owner; native execution is not a substitute for the exact-Wasm fork test.

Current live markers show the reward-point remap, VAL reward publication and BABE repair already applied. Their live-state path is therefore an idempotence check. Active historical migration branches require the separate native/synthetic fixtures. Full Staking/XorFee data preserves real reward budgets and claims for migration hooks, but this test does not pay real accounts or prove aggregate payout correctness. The native zero-submission claim is based on source review: remote-externalities uses read-only RPC methods and Executive runs locally. No native transport allowlist or packet counter is installed, so this is not an independent network-traffic measurement. No transactions, governance submissions, offchain workers or validator deployment occur in that reviewed path.

At preparation time the native execution status is **not run**. Consult `native-remote-execution.json` for the actual result; preflight success alone is not native execution success.
